# Constraints

本项目的硬约束。这些不是偏好，是**违反了就会让结论失效**的规则。

---

## 1. P4A 数据的用途边界

P4A 的历史数据（session 日志、`experiments/p4a/` 下已有代码）是既成事实。

1. **只读、不可变**。不应为了"配合新研究"而修改或重跑。需要新的分析逻辑，写在**分析脚本**
   里，不要改动原始日志或 p4a 自身流水线代码。
2. **代码隔离**。`experiments/p4a/` 保持独立、少改动，不与 CachePlan 核心方法代码耦合。
   确认被多个实验复用的部分（轨迹解析、cache 命中率计算等）才下沉为共享分析工具，且放在
   CachePlan 自己的代码路径下，**不塞进 `experiments/p4a/` 内部**。
3. **用途边界**：P4A 数据只能用于**诊断性/动机性分析**——问题规模刻画（token 放大倍数
   分布）、轨迹方差分析（语义等价但表达不同导致的前缀差异）、system-reminder 等注入内容
   对轨迹的影响。
   **不能**直接作为"CachePlan 方法是否有效"的对照组基线：其模型与 serving 环境与主实验
   大概率不同，且**离线日志无法反事实重放一个改变了 agent 行为的新策略**。方法有效性的
   验证仍需在同一套 infra 上重新跑受控对比。
4. **派生产物存放**：任何从 session 日志聚合出的表/图写入 `data/processed/`（gitignored），
   并标注数据来源（源自哪个 tar.gz 版本、生成脚本、生成日期），保证可追溯。
5. **泛化边界**：P4A 的轨迹结构（长 ReAct 循环、固定 skill 模板、MinerU/vLLM 特有的工具集）
   比较特定。样本实验部分若要支撑更普遍的结论，应补充**至少一个结构不同**的批量 agent
   工作负载，不能只靠 P4A 一个案例撑起"批量 agent 场景"的泛化论断。
6. **引用规范**：在报告/论文中提及 P4A 数据时，明确标注为"案例研究"或"动机性观测"，与主
   实验的受控结论**分节陈述**，避免使用暗示因果验证的措辞（如"证明了""因此方法有效"）。

## 2. 先决核查项：cache 结论的闸门

> **批量核实全部 12,801 个 session 的 `inputCacheRead` / `inputCacheCreation` 是否恒为 0。
> 未做之前不得下结论。**

分支后果：

- **若非恒零**：可以计算真实 cache 命中率分布，作为强证据使用。
- **若恒为零**：说明该字段在这套 openai 兼容 provider 下未被正确采集，只能退回基于 prompt
  前缀 token 重叠度的**代理指标**，**报告中必须明确标注这是估算值而非真实命中率**。

这条闸门管的是**一切基于 cache 命中率的结论**，不只是某一条 claim。对应 **E01 阶段 1**。

## 3. staged 文献规则

精读稿落在 gitignored 的暂存区，**不是成品**。

> 精读稿由 agent 生成，**必须经人工评审确认结论可信之后**，才决定是否以及以什么形式进入
> `docs/literature/`——通常是提炼成一篇判断笔记，而不是把长稿整篇搬过去。未经评审的内容
> 不进 `docs/`，`refs.bib` 的 note 字段也不写它的结论。

**本 artifact 对这条规则的处理**：staged 结论被**记录**（因为它们是真实发生过的推理轨迹，
删掉会让 trace 不诚实），但被显式标 `Status: staged`，**不承担论证责任、不可对外引用、
不得用来支撑决定**。当前 C04–C08 全部处于此状态。

另一条相关规则——**入库门槛**：一篇论文进入 `refs.bib`，必须能说出它支撑哪个 open
question / decision / experiment。不做无目的的文献囤积；只读不入库是允许的，读完发现无关
就不要留下痕迹。

## 4. 上下文卫生规则（对 agent 的约束）

两条同源的规则，目的都是防止已收敛的长文本反复占用上下文：

1. 一个 open-question 一旦被标记 `RESOLVED`，其原始文档即为历史记录，**不要在未被用户
   明确要求的情况下读取它**——只参考 PROGRESS 表中的 Resolution 摘要。
2. 文献默认只读索引表的行，以及需要时某篇笔记的 `verdict` 字段。**不要把 PDF 全文或整篇
   笔记拉进上下文**，除非用户明确要求某一篇。

## 5. 工程约束（来自 AGENTS.md 的 Working Principles）

1. 保持实验可复现。
2. 偏好小而可检查的改动。
3. **不得静默改变实验配置或评测行为。**
4. 保持 cache 相关的 instrumentation 与执行轨迹可观测。
5. 除非实验需要，不引入非确定性行为。
6. **明确区分实验性机制与基线实现。**
7. 不要仅为了软件优雅而优化代码，当这样做会让实验更难理解或复现时。

## 6. 本 artifact 自身的已知缺口

诚实记录，不掩盖：

| 缺口 | 影响 |
|---|---|
| B01 的分析逻辑没有落成脚本 | 单 session 复现结果目前不可自动重跑；E01 必须补上 |
| **本项目尚未完成任何实验** | 所有 `supported` 的 claim 都靠继承观测或代码事实，不靠 E-series |
| `refs.bib` 在 cache 方向上完全为空 | 本项目在自己的主线方向上尚无文献工作 |
| 无第二个 workload | 约束 5 要求的泛化前提未满足 |
| CachePlan 自身的方法代码尚不存在 | `src/` 只有 P4A 这个历史项目 |
