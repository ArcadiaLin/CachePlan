# Experiments 抽取设计

日期：2026-09-20。状态：设计稿，未实施，未改 `schemas.py`。

本文档只管实验条件与结果的组织形态。总体设计见 `docs/designs/main.md` 第 4 节。
基线是 `docs/discussions/2026-09-13-layer4-schema-proposal.yml`（Layer4 schema v3 提议稿），
不是更早的 `p4a-v1-protocol.md`。

## 结论

**基本沿用 v3，不增加结构。** 第 7 节记下的"宽松 schema vs 条件可逐项比对"这个硬冲突，
不需要用键值化的维度模型去解——它在很大程度上是个假问题：跨论文筛选靠的是**值**，
不是把条件拆成受控维度。

本文档在 v3 之上只做四件事，每件都很薄。

### 已定：条件是自由的名值对，不设维度词表（2026-09-20）

沿用 v3 现状，且明确 `dimension` 不受控：

```yaml
conditions:
- dimension: context_length                    # 自由串，论文怎么说就怎么记
  values: '4k / 8k / 16k / 32k / 64k / 128k'   # 原文串，不归一、不拆子字段
  evidence: {origin: paper, section_id: sec-4, paragraph_index: 55, char_span: [...], quote: '...'}
```

三条理由：

1. **筛选发生在值上，不在维度名上。** "找用 A100 的工作"是对值做子串/语义匹配，
   `8 × A100`、`A100 40G PCIe`、`A100` 都能命中。维度名只在投影（把 N 篇的硬件列成表）
   里才需要，而 N 篇短串 Agent 直接读。
2. **预设词表必然漏，且漏得有害。** 漏掉的维度会被抽取方塞进最近的那个名字里，
   比不受控更糟。这正是第 4 节要"宽松"的原始动机。
3. **不丢信息，可后悔。** 维度名归一若以后真的需要，是一次后加的派生，原文串永远在。

代价：按维度分类的聚合（"已读的 N 篇里有多少篇报了硬件"）算不出来。接受——
第 1 节标准 3 的覆盖声明落在结构性统计上（多少篇有 condition 记录、多少条结果有定位），
不需要按维度分类。

**2026-09-20 放弃的设计**（记下来，避免以后重新提）：维度注册表（维度作为带版本的记录）、
取值拆成受限子字段（`{model: A100, mem: 40G}`）、evidence 下沉到子字段。放弃理由是
它们买到的是"库自己判出 mem 冲突"，而按第 1 节"库提供信息，不提供判定"，
这件事本来就该由 Agent 读一眼完成；为它付一整套本体化代价不值。

### 已定：归一只做在当连接键的实体上（2026-09-20）

跨论文对齐的成本只花在会被别的节点连边的东西：dataset / benchmark / model / metric。
v3 已用 `resources_used[].resource_id` 承载，不新增机制。

`8 × A100` 不做归一，因为图里没有 A100 节点，没人从它出发连边。
AgenticScholar 的做法一致：它归一 Dataset / Metric / Baseline，不归一实验设置本身。

### 已定：精细化按需派生并回写（2026-09-20）

少数维度确实需要范围筛选（`context_length > 32k`），原文串 `'4k to 128k'` 做不了。
处理方式不是建库时全量铺开，而是：

> **第一次真的要按它精筛时才派生，派生结果作为一条带归属与观察时间的记录回写，只追加。**

这不是新机制，是第 7 节已定的按需刷新换个地方用：不在建库路径上无条件计算，由实际需要驱动。

**这也是与 AgenticScholar 查询时抽取的唯一实质差别。** 它每次查询重抽一遍，同一问题两次
可能得到不同数字；我们抽一次写回去，因而第 7 节的 as-of 查询成立、第 1 节三条成功标准
报得稳。这个差别很便宜，值得留；其余的重装备不值。

### 已定：论文级默认靠 locator 区分，不建继承链（2026-09-20）

全文说"实验在 A100 上跑"、Table 3 又说"该组用 8 卡"时，落盘一律扁平——
继承来的取值其 `evidence` 指向 setup 节，局部报告的指向表格附近。

不额外花钱，且第 8 节白赚一条：论文改版时 setup 那段被改，所有 evidence 指向那段的条件
一次性全被标待复核，跨 experiment 生效，不需要父节点失效传播。

### 已定：result 不预抽数值（2026-09-20）

沿用 v3 的 `result_refs: [table_id]`，只存"到哪里找"，不存"是什么"。数值按需抽取并回写，
规则同上。

理由是成本与错误率：v3 附录 C 第 1 条已经警告新字段比旧字段难核验，全表逐单元抽取是
最难核验的一类。若试抽显示定位到表仍不足以支撑 Q1，再考虑抽取论文正文明确陈述的关键数值。

## 待确认

- **三态命名。** `main.md` 第 4 节写 `unchecked / absent / not_applicable`，v3 写
  `not_checked / not_found / not_applicable`。倾向统一用 v3 的命名（更接近产物与代码）。
- `field_status.source`（`paper_claim / external_observation / inferred`）与 Q5 要的
  三层证据（声称 / 外部观察 / 复现）不完全对齐，v3 缺"复现"一档。**暂不拆字段**，
  等真的要做 Q5 时再说。

## 未解决

- 按需派生的触发形态：由谁发起、回写到哪、与 Layer4 产物的关系。
- 表格定位依赖 MinerU `content_list` 的表结构解析质量，未验证。
- v3 附录 C 第 1 条的风险仍在：`conditions` 若没有独立小样本标注，可能只是变长的自由文本。
  试抽后某字段抽不稳定就删，不留空占位。
