# 查询算子：候选查找的定位与实体身份问题

日期：2026-09-28，2026-09-29 更新。状态：部分已由当前方案回答（见"已回答"）；身份的积累与修正、查找效果的测量仍开放。

## 问题

抽取 Agent 在写入共享节点前，先用查询算子查找图中是否已有同一对象，据此复用节点、连边或新建。需要回答：

1. 这一步的模糊查找是工程组件，还是论文需要专门设计和解释的机制？
2. 能否靠多写 `aliases` 覆盖各种称呼，绕过复杂的查找？
3. 是否应增加 embedding、关键词等索引层，并作为方案的一部分？

## 已回答

当前方案见 [查询算子](../designs/operator.md)，实现于 `experiments/e08/notebooks/06_extract_prepare.ipynb` 第二节。

**问题 1：按工程组件实现。** 按称呼找回同一对象即实体解析 / 实体链接，数据库领域已有成熟流程（blocking + matching，如 Magellan、Ditto），知识图谱有实体对齐，RAG 系统中混合检索也已常见。算子采用标识解析 + 多路召回 + RRF 融合，都是已有技术的组合，不作为贡献。算子只返回候选及各通道证据，不给置信度，不设阈值，是否同一对象由 Agent 判断。

**问题 2：不靠堆 aliases 绕过。** aliases 只用于 Stage 1 的精确标识匹配，含义保持为"已确认指向同一对象的称呼"；标识解析只做大小写与标点归一化，不做缩写还原。理由：

- 未读论文会带来新的写法，预置无法穷尽；知识库要解决的恰是阅读新材料时的查找。
- 为召回塞入扩展词会破坏 aliases 的含义（`data/raw/e08-paper-knowledge/seeds/README.md` 已约定扩展词由检索工具处理）。
- 难点多在分辨而非召回：ETT 与 ETTh1（整体与部分）、GPT-3.5-turbo 与 `-1106`（模型族与快照）、RevIN 与一般归一化概念（具体方案与上位概念）。这些依靠关系和版本表达，不是别名。候选随附一跳邻接关系（如 `PART_OF`），供 Agent 分辨层级。

**问题 3：两类索引都已加入，但作为组件的组成层次，不作为贡献。** 名称用全文索引（原词、前缀、模糊匹配），定义与陈述用 `english` 分词的全文索引（BM25），语义用 Qwen3-Embedding-8B 向量索引。

这偏离了原先"先测漏找类型、再决定是否加 embedding"的建议：种子只有几十个节点，无法测出有意义的漏找分布，而六篇论文需要尽量高质量地入库，因此先建完整检索层，入库后再用消融检验各层的作用。

## 仍开放

**查找效果的测量。** 六篇论文入库后，用抽取运行日志中的真实查询和 Agent 的复用决定作为测试数据：

- 漏找率与漏找类型（写法变体、缩写、分词、语义改写）；
- 各通道的消融：对召回率和重复节点数的影响；
- 已知问题：定义通道与语义通道都读 description，存在重复计数；查询 ETTh1 时 ETT 排名下降（见 operator.md）。

**aliases 的积累作为证据。** 每次确认复用，原文写法追加进 aliases，后续论文的精确命中率应随之上升。可按阅读顺序统计精确命中率与重复节点比例，说明知识库在使用中积累；这是测量对象，不是新机制。

**身份作为可追溯、可修正的知识。** 若身份问题进入论文叙事，重点应在此，而非匹配算法：

- 复用 / 新建 / 暂不确定的判断带依据，作为增量记录；
- 判断可修正：合并或拆分节点时，相连的主张、实验和使用记录如何迁移；
- 版本与粒度（族与型号、数据集与切分）作为身份的一部分，不被静默合并。

这与 AGENTS.md 中"不静默合并不兼容的实体、条件和版本"一致。能否构成贡献，取决于整体机制确定后的定位；待首批抽取暴露真实的身份错误后再判断。
