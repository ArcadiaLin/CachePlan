# 查询算子：候选查找的定位与实体身份问题

日期：2026-09-28。状态：开放问题，以下是讨论中的判断与建议，尚未定论。

## 问题

抽取 Agent 在写入共享节点前，先用查询算子 `find_entities`（`experiments/e08/notebooks/06_extract_prepare.ipynb` 第二节）查找图中是否已有同一对象，据此复用节点、连边或新建。需要回答：

1. 这一步的模糊查找是工程组件，还是论文需要专门设计和解释的机制？
2. 能否靠多写 `aliases` 覆盖各种称呼，绕过复杂的查找？
3. 是否应增加 embedding、关键词等索引层，并作为方案的一部分？

## 当前判断

**模糊查找本身不宜作为贡献。** 按称呼找回同一对象即实体解析 / 实体链接，数据库领域已有成熟流程（blocking + matching，如 Magellan、Ditto），知识图谱有实体对齐，RAG 系统中混合检索也已常见。"增加一层 embedding 或关键词索引"若没有针对论文知识的特有难点，只是已有技术的组合。

**不靠堆 aliases 绕过。** 理由：

- 未读论文会带来新的写法，预置无法穷尽；知识库要解决的恰是阅读新材料时的查找。
- `aliases` 是数据产品的一部分，含义是"已确认指向同一对象的称呼"；为召回塞入扩展词会破坏这个含义（`data/raw/e08-paper-knowledge/seeds/README.md` 已约定扩展词由检索工具处理）。
- 难点多在分辨而非召回：ETT 与 ETTh1（整体与部分）、GPT-3.5-turbo 与 `-1106`（模型族与快照）、RevIN 与一般归一化概念（具体方案与上位概念）。这些依靠关系和版本表达，不是别名。

**aliases 的积累可以作为证据测量。** 每次确认复用，原文写法追加进 aliases，后续论文的精确命中率应随之上升。可按阅读顺序统计精确命中率与重复节点比例，说明知识库在使用中积累；这是测量对象，不是新机制。

## 可能进入论文叙事的部分

若身份问题进入叙事，重点应是"身份作为可追溯、可修正的知识"，而非匹配算法：

- 复用 / 新建 / 暂不确定的判断带依据，作为增量记录；
- 判断可修正：合并或拆分节点时，相连的主张、实验和使用记录如何迁移；
- 版本与粒度（族与型号、数据集与切分）作为身份的一部分，不被静默合并。

这与 AGENTS.md 中"不静默合并不兼容的实体、条件和版本"一致。能否构成贡献，取决于整体机制确定后的定位，目前只是候选。

## 建议做法

1. **查询算子按工程组件实现，复杂度由数据决定。** 06 notebook 2.2 用六篇论文原文中的称呼批量查询，统计漏找数量及类型（写法变体、缩写、分词、语义改写）。
   - 以写法与分词为主（如已观察到标准分词下 `ETTh1` 召回不到 `ETT`）：调整分词、n-gram 或前缀匹配即可。
   - 语义改写占比明显：再考虑 embedding 层。
2. **论文中如实描述为组件。** 说明组成层次，以消融报告召回率及对重复节点数的影响。
3. **身份的积累与修正保持开放**，待首批抽取暴露真实的身份错误后，再判断是否值得作为研究问题展开。
