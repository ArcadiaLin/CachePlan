# E07 — P4A 样例论文集构造

状态：2026-09-11 按用户确定的五步路线整合。E07 已完成初始语料复制；种子与噪声筛选、扩展、ground truth 核查和案例选择尚未完成。本次更新整理目标与已有案例，不执行新的筛选或评测。

背景：[Papers for Agents：讨论与备忘](../../discussions/2026-09-09-paper-for-agents.md)。工程入口：[E07 README](../../../experiments/e07-p4a-case-pool/README.md)。

## 目标与文档分工

从现有 P4A v1 成果出发，构造一个具有可核查 ground truth 的论文候选池，用于寻找有“选择转折”的代表性 query，并为后续整组 QA 评测准备材料。第一版以至少约 200 篇论文及其相关资源为规模目标；最终组成取决于需求覆盖与核查结果，不预设正负例比例。

案例来自这个候选池，是其中一个 query 的完整展开。它应展示：

> 具体研究需求 → 初始候选 → 资源或引文提供新线索 → 发现新论文或修正候选判断 → 得到有证据支持的阅读选择。

代码、benchmark、dataset、引文信息中的一种或几种发挥实际作用即可，不要求每个案例覆盖所有资源类型。论文集与整组 QA 支撑工程评价，代表性案例解释其中的具体过程；不再独立拼接一个脱离候选池的故事。

本实验文档集中于 `docs/experiments/e07-p4a-case-pool/`，与工程目录对应。`README.md` 为总入口，两份案例清单保留各自来源，统一使用下述案例模板与全局编号：

- **本文**：目标、五步主线、ground truth、交付要求、全部案例索引，以及 A/B 的合并描述。
- **[案例清单 C–H（Claude 来源）](case-candidates-claude.md)**：保留该来源提出的六个案例；其 A/B 补强已并入本文。
- **[案例清单 I–M（Kimi 来源）](case-candidates-kimi.md)**：原 C–G 依次改为 I–M，避免编号冲突；其 A 补强已并入本文。

已有建议均作为待对接语料的线索保留。原先对某案例的推荐强度是提出者的初判，最终选择按五步路线中的实际材料与核查结果决定。

## 数据基础与当前进度

根据 [v1 数据说明](../../../data/raw/p4a-v1/README.md)，本地副本包含 3321 篇 ACL 2025/2026 论文的处理产物，各层覆盖不完全相同。E07 从“961 观测集”中复制了 952 篇不同论文，作为初始筛选语料。

现有 [p0 报告](../../../data/processed/e07/p0_corpus_summary.json)记录了 952 篇的复制结果、逐层文件数与字节数校验，以及 20 篇抽样哈希比对。复制内容为全文 markdown、Layer4 记录和 cite 材料；原 PDF 等材料需按来源另行定位。已登记缺口为 `2026.acl-long.165` 缺少 `layer4/agent_judgment.json`。

952 篇是初始筛选范围，不是已经标注好的最终候选池。后续关系扩展可以进入其余 v1 论文，也可以从 ACL 扩展到 venue 外。语料外论文先登记为线索；成为正式正例、负例或案例证据前，要补齐相应判断材料。

v1 的描述、关系类型、证据与可得性字段均有待复核。完成过资源抽取意味着有可供检查的材料，并不自动建立需求相关性或资源事实的 ground truth。当前以 Layer4 为基础；本地副本已移除 layer4_v2，原始归档未改动。

## 筛选主线：用户确定的五步路线

先为候选 query 记录研究需求和可检查的满足条件，随后按以下路线组织数据。A/B 是起点，其他案例也可以提供需求；不要求全部推进。

1. **种子集：从 P4A 已处理的论文里选一批真阳性。** 优先寻找完整跑过资源抽取、代码/数据/benchmark 关联材料可核查的论文。先根据资源数量、记录类型和 URL 等结构性信号定位候选，再依据原始材料核查其是否满足具体 query，确认后标为种子正例。
2. **第一批噪声：同 venue、表面相关但实际不满足需求的论文。** 以关键词、主题和任务描述接近的论文构成困难候选；明确其不满足哪项条件。不能因为论文被当作噪声采入，就直接赋予负例标签。
3. **向外扩展：沿引文、共享代码库、共享数据集等关系，从 ACL 扩展到 venue 外。** 保留从种子到目标论文的路径、关系含义和来源。重点寻找资源链可达、初始检索没有命中的正向候选；是否难以被合理关键词检索发现，需要实际检索记录支持。
4. **第二批噪声：扩展过程中捎带进来的不相关论文。** 保留这些自然出现的干扰项，记录它们为何被带入、又为何不满足当前需求。共享资源只提供候选关系，不自动建立研究相关性。
5. **从候选池筛选有“选择转折”的代表性案例。** 选择需求明确、正向候选可核查、关键线索确实改变发现或判断的 query，写成一页案例，并关联回池中论文、资源与标签。

“种子 / 同 venue 困难候选 / 关系扩展 / 扩展干扰项”记录候选进入池子的途径；“满足 / 部分满足 / 不满足 / 证据不足”记录对具体 query 的判断。两者分别记录，且一篇论文对不同 query 可以有不同标签。

如果某个外部建议暂时找不到本地种子或可核查扩展路径，保留为备选；不直接把外部名篇清单当成已完成上述路线的候选池。

## Ground truth 与取证要求

Ground truth 分为两层，均需保留证据与核查状态：

| 层次 | 要确认什么 | 记录要点 |
| --- | --- | --- |
| 资源与关系事实 | 哪篇论文引入、使用或比较了什么资源；资源身份、版本和关系是否正确 | 论文与资源标识、关系、论文页码或章节、仓库 commit 与文件、数据版本或样例、引用上下文 |
| 相对于需求的判断 | 论文满足哪些条件，哪些不满足，哪些仍未知 | query 与条件版本、候选论文、逐项判断、支持和反对证据、核查者与时间 |

已有抽取结果作为标注线索；最终标签需依据原始材料复核，不能用待评系统自身的输出直接充当标准答案。找不到证据时保留“证据不足”，不归为负例。Ground truth 的完整性限定于已核查的候选范围，不声称覆盖整个领域。

同时记录：

- 查询词、入口、工具、日期、关键候选与发现顺序；缺少历史记录时标为重建。
- 扩展边的起点、资源或引用、终点与证据；区分“存在引用 / 共用资源”和“复用实现 / 扩展方法”等不同关系。
- 加入关键线索前后的候选判断，以及改变判断的具体原因；说明线索来自正文、代码、数据、benchmark 还是引文。
- 材料事实、作者声称、执行者推断与未知事项；观察代码、执行成功、实验复现分别记录。
- 合理查询改写、正文阅读与常规引文追踪能否取得同样线索。标题未出现某词不能证明检索一定失败；外部资源存在也不能证明其具有额外作用。

## A：从 Agent 执行轨迹寻找可复用经验

**来源与状态：** 用户真实检索经历及其与另一 Agent 的复盘；合并 Claude、Kimi 的补强线索。历史经历、后续重建与新候选须分开记录，尚无已完成的正负例标注。

**研究需求 / query：** 寻找把 Agent 执行轨迹组织、抽象并用于后续任务的研究，说明输入、加工产物和复用方式。产物可以是 workflow、plan、skill、execution pattern，也可以服务系统优化。是否要求“自身生成的经验”、跨任务或跨站点复用，需要在 query 中明确，不能为排除某论文事后收紧条件。

**已有候选与材料：**

- 用户初始检索使用 agent trace、agent trajectory、long agent history，提及 DeepPrep、LongDA；准确身份与机制仍待确认。
- [AWM / Agent Workflow Memory](https://arxiv.org/abs/2409.07429)及其 [mind2web 目录](https://github.com/zorazrw/agent-workflow-memory/tree/main/mind2web)：线索涉及从轨迹归纳 workflow、offline 轨迹来源与按站点组织。
- [SkillWeaver](https://arxiv.org/abs/2504.07079)、Agent Skill Induction、[ExpeL](https://arxiv.org/abs/2308.10144)、[Voyager](https://arxiv.org/abs/2305.16291)：可考察技能 API、离线经验提炼、模型依赖和任务环境；Agent Skill Induction 的论文身份待补齐。
- [Synapse](https://arxiv.org/abs/2306.07863)：原建议以 `build_memory.py` 中演示数据的来源提出潜在负例，需结合 query 核查。
- WebArena、Mind2Web 的使用关系和后续引文，是从本地论文连接上述候选的潜在入口。

**五步路线中的入口：** 从 v1 中与 Agent、轨迹、记忆或上述 benchmark 有关的论文定位并核查种子；加入同 venue 的历史上下文管理等困难候选；沿 benchmark、代码和引文向外扩展，同时保留只共享环境、并不满足经验复用要求的候选。

**预期选择转折：** 从“处理历史上下文”这一表面相近的候选集合，进一步找到或辨认出真正符合当前复用条件的工作。上下文管理与经验复用可以重叠，不强行二分。

**核查重点：** 输入是单次历史还是多次执行、人工演示还是自身轨迹；产物是摘要、检索记忆还是可执行技能；何时构建、用于当前任务还是新任务、如何影响执行。核查 AWM 的 offline 设定、Synapse 的演示来源、ExpeL 的离线阶段与 GPT-4 依赖、Voyager 的 Minecraft/JS 与环境准备要求。原建议的 AWM 增益数字与 venue 归属均需回源；不直接采用复盘中的说明性数字。Synapse 是否为负例取决于需求，人工准备环境也不自动反驳任务内自主执行的声称。

**可复用记录与限度：** 保存轨迹来源、经验产物、构建/调用阶段、复用范围和 benchmark 关系。已有建议没有证明普通检索无法找到这些论文；代码中的设定差异也不自动构成检索转折。此案例不恢复仓库旧有的优化研究方向。

## B：为长上下文指令遵循研究寻找相关工作

**来源与状态：** 此前讨论构造的研究需求，合并 Claude 的具体论文线索；不是已经发生的用户检索经历。Kimi 对有效上下文长度的建议另存为 L。

**研究需求 / query：** 为改善长上下文中指令遵循的方法寻找相关工作及可用评测，关注上下文长度、指令所在位置、约束类型与遵守情况。

**已有候选与材料：**

- [LIFBench](https://aclanthology.org/2025.acl-long.803/)：作为长上下文指令遵循的正向候选线索，核查任务与 LIFEval 评分。
- [IFEval](https://arxiv.org/abs/2311.07911)：核查 `google-research/instruction_following_eval` 中可验证约束、registry 和判定实现。
- [RULER](https://arxiv.org/abs/2404.06654)、[HELMET](https://arxiv.org/abs/2410.02694)：考察其任务与指令遵循需求的重合和差异，不预先全部标为负例。
- LongBench v1 与 [LongBench v2](https://aclanthology.org/2025.acl-long.183/)：通过数据样例和评分方式判断版本差异对适用性的影响。

**五步路线中的入口：** 从 v1 的长上下文、指令遵循或相关 benchmark 使用论文中找种子；加入同 venue、主题相近但目标能力不匹配的候选；沿任务、数据、评分实现与引文向 venue 外扩展，保留只共享“长上下文”主题的干扰项。

**预期选择转折：** 从笼统的“长上下文评测”候选，转向能回答具体指令约束需求的论文；资源选择作为后续行动，先确认资源信息如何改变论文发现或适用性判断。

**核查重点：** 区分检索、推理、指令遵循与稳定性；检查指令位置、样例、可验证约束和评分版本。原建议提到 LIFBench 的 3 场景、11 任务、2766 条指令，IFEval 的 25 类约束，LongBench v2 的 503 道题和 8k–2M words，以及 HELMET 的模型数与相关性数字，均是待回源线索。不能由“存在评分代码”推断正文无法说明任务定义。

**可复用记录与限度：** 保存任务能力、约束类型、长度与位置设置、评分条件和使用关系。需求调整要记录原因；如果正文或常规引文追踪已经足够，应限定外部资源的增量作用。

## 阶段衔接与预期交付

E07 保留 p0–p4 的阶段划分；实现状态以其 README 和产物为准：

| 阶段 | 与五步路线的关系 | 后续交付 |
| --- | --- | --- |
| p0 | 准备初始语料 | 已有 952 篇复制子集与校验报告 |
| p1 | 为种子定位和向外扩展准备线索 | 可回到原始记录的 paper–resource 边及引用入口，语义状态待核查 |
| p2 | 步骤 1–2 | 需求条件、种子正例、同 venue 困难候选及逐项判断 |
| p3 | 步骤 3–4 | 扩展路径、外部材料、新增候选及扩展干扰项 |
| p4 | 步骤 5 | 候选池与标签汇总、QA 草案、代表性案例及限制 |

种子阈值、噪声比例、扩展深度和边优先级在看清本地材料后确定，不在文档中提前写死。未实现阶段的脚本与运行另行按仓库工作节奏推进。

预期交付包括：

1. **候选池清单：** 论文标识与版本、进入池子的途径、关联 query、材料位置和缺口；报告与约 200 篇规模目标的差距。
2. **关系与标签证据表：** 资源事实与需求判断分层，保留支持、反对、部分满足及未知项。
3. **QA 与候选比较：** 每个需求的条件、答案范围、核查依据，以及各案例能否对接本地种子和扩展路径。
4. **一页代表性案例：** 需求、初始候选、关键线索、选择转折和最终阅读选择；标明真实经历、构造需求与重建步骤。
5. **P4A 的启示与限度：** 哪些信息适合持久保存和复用，哪些判断依赖 query；包括没有出现转折、普通检索已足够的结果。

## 与后续评测的关系

当前工作首先构造并核查候选池。材料可以支持后续 QA 评测，但 v1 抽取产物和探索阶段的案例不能直接证明方法有效。

后续可比较使用 P4A 资源库、Agent 直接检索和外部 DeepResearch 的回答。正式比较前需确定 QA、证据范围、质量标准和预算：同材料访问的比较用于分析资源库贡献，开放检索比较用于观察实际效果；构建成本与查询成本分别记录，保留未用于调试的问题。Ground truth 与标准案例叙述属于标注材料，不作为待评系统的额外答案输入。

总体优势由整组 QA 的结果判断；选中的案例用于解释具体机制。未完成核查的外部线索不计入有 ground truth 的评测范围，也不预设 P4A 必然优于其他系统。
