# KATS：任务导向数据集检索与 agent-ready artifacts 的比较边界

## 它说了什么

KATS（Knowledge graph-Augmented Task-oriented dataset Search）解决一个明确问题：给定固定论文语料和自然语言研究任务，返回语料中相关的唯一数据集实体排名及简短解释。它将论文中“某数据集被用于某任务”的使用经验加工成持久知识库，再服务后续资源发现（§3–6）。

核心流程是：**论文转文本 → 筛选与用途抽取 → 构建任务—数据集知识图谱和向量索引 → 实体整合 → 任务检索与图扩展 → 数据集排序。**

| 环节 | 方法与作用 |
| --- | --- |
| 文档处理 | pypdf 提取文本，内容指纹用于缓存；图表不是主要信息来源。 |
| 三阶段抽取 | Preliminary Filtering Agent 判断是否使用数据集；Analyst Agent 抽取数据集与用途；Enrichment Agent 补充任务关键词。公开实现主要是固定阶段的 LLM 调用。 |
| 结构化表示 | 论文、数据集、任务三类节点；论文—数据集、数据集—任务、相似任务三类边。任务描述保存具体用途，数据集保存名称与简介等信息。 |
| 任务链接 | 对相似任务增加加权边，保留原始用途节点；不直接将所有相似任务合成一个任务。 |
| 数据集消歧 | 向量近邻生成候选，结合名称规范化、别名字典及 LLM 同一性判断，通过并查集合并。 |
| 在线检索 | 向量检索种子任务，PPR 扩展任务图；数据集分数取关联任务分数的最大值，再交给 LLM 重排。 |
| 增量更新 | 对新文档抽取、追加数据库和向量索引，让新实体与已有知识链接或合并。 |

公开抽取提示词要求任务描述不包含数据集名称，使向量主要表达“用来做什么”。主实验使用 gpt-4o-mini 和 text-embedding-3-small，初始任务候选数为 2，PPR 的 $\alpha=0.85$（§7.1.4）。没有训练新的表示模型。

## CS-TDS 评测集如何构造

作者从真实论文的资源使用情境出发，由 LLM 生成自然语言任务，人工核验并选取测试问题，以论文实际使用的数据集为初始答案。产生问题和答案的来源论文从搜索语料中留出，要求系统通过其他论文找到相关资源；留出的不是目标数据集本身（§3.2）。

| 统计量 | CS-TDS M | CS-TDS L |
| --- | ---: | ---: |
| 论文数量 | 628 | 2,101 |
| 测试问题 | 47 | 204 |
| 数据集记录数，原表约数 | 1,779 | 7,525 |
| 唯一数据集数，原表约数 | 1,217 | 4,180 |
| Table 1 标注年份 | 2022、2023 | 2024 |

正确答案除原始数据集外，还接受别名、变体及功能上合理的替代资源，例如用于相同目标的同系列不同规模数据集。作者在评测时人工比较输出，以减少假阴性（§3.2.3、§7.1.1）。

**这一口径主要评价候选发现。**同系列或同用途的数据集都可被认为相关，但它们未必满足相同预算、划分、许可或评测协议。检索相关性与具体实验中的可互换使用应分别判断。

精读时核查的公开 Build CSV 全部为 NeurIPS 论文链接：M 的 URL 年份为 2022 年 284 条、2023 年 344 条；L 为 2024 年 2,099 条，另各含一条 2022、2023 链接。这里是 URL 清单统计，未逐篇核实出版年份。公开 Test CSV 只有 task、ground_truth、link，缺少问题来源论文 ID、完整替代答案集合及人工裁决记录，不能仅凭这些字段独立重建全部人工判分。详见[精读稿](../../references/papers/2026-KATS/analysis.md)及[固定版本辅助材料](../../references/papers/2026-KATS/supplement/README.md)。

最值得借鉴的是**用途作为连接研究意图与资源的中间表示**，以及任务、数据模型、方法和评测之间的对应关系。明确的检索目标也解释了其只抽取部分内容、控制表示规模的取舍。

## 边界与差异

- **检索质量不等于产物语义质量。** Hit@5 衡量前五个结果是否有相关答案；EM 和 token F1 主要评价 top-1 数据集名称。它们不直接评价用途关系、实验条件或证据是否正确。作者在 §9.2.2 明确承认缺少依据源文核验并纠正抽取事实的专门模块。
- **不能说 KATS 完全没有上下文、来源或版本区分。** 任务描述保存具体用途，导入记录有 document_id；公开消歧提示词要求区分年份、版本和 train/test split。相关性评测允许多个版本作为答案，不意味着消歧时将它们视为同一实体。见[本地同一性提示词](../../references/repos/KATS/src/task_oriented_dataset_search/graph/prompts/dataset_identity_prompt.txt)。
- **版本身份区分仍不等于使用条件核验。** 本文没有系统评价论文、某次实验、资源版本、数据划分和外部实现之间是否正确对应；字段级证据和未知/冲突状态也没有成为完整的评价对象。
- **动态能力主要体现为新增入库。** §5.5 还允许根据相似数据集为外部简介联系任务，因此不宜说它绝对只支持论文。相似性迁移的任务关联，仍需与直接观察到的使用事实区分。
- **效果归因和泛化证据有限。** 问题量和来源覆盖有限，缺少置信区间与若干关键独立消融；Table 8 与在线研究 Agent 的比较只有两个案例，材料访问和离线投入也不同。
- **存在报告不一致，不能照抄结论。** L 上 73.0% 与 60.8% 的差距是 12.2 个百分点，原文误写成接近 20 个百分点；Table 9 中 GSM8K、GLUE 的任务描述与前页正文对调。后者可能是排版或转录问题，缺少原始 trace 时不能据此判定实际系统错误，但该表不足以证明关系抽取准确。

这些边界说明尚缺什么证据，不证明 KATS 无法通过扩展获得相关能力，也不直接确立我们的新颖性。

## 对我们研究计划的启示

### 研究对象与创新性

保留“将论文及关联材料转化为 agent-ready artifacts”的整体目标。KATS 已覆盖论文预加工、用途知识抽取、实体整合、持久保存和自然语言查询；更广的资源种类、更多接口或更多 Agent 不能单独承担主要贡献。

当前值得继续讨论的核心问题是：**如何构造带有证据与适用条件的研究产物，使 Agent 能够在不同研究任务中正确复用？** 产物可承载方法说明、结论证据、实验协议或资源使用记录；资源使用记录可以作为第一个可验证切面，不预先限定全部研究范围。

候选技术特色包括：

1. **跨材料对应。** 将论文、表格、配置、数据说明和评分代码对齐到同一实验及资源版本，避免各字段分别真实、组合关系却错误。
2. **事实核验与状态表达。** 区分作者主张、材料观察、实际执行和推导判断，保留缺失、冲突与检查范围。证据链接存在不代表证据支持断言。
3. **有条件复用。** 保存可复用事实，将当前任务下的适用性判断单独表达；条件改变时重新判断，必要时补充核查。

差异可以在同一资源已被正确检索出来之后成立：Agent 仍需要确认采用哪个版本、子集和协议，以及材料是否支持预期用途。上述内容是候选研究定位，尚未确定 schema、机制或 benchmark；KATS 自身也提出未来增加事实核验，因而“加一个 fact checker”仍需具体技术与实验增量。

### 为什么选择 CS 作为初始实证范围

论证应从 Agent 利用研究的需求出发，再说明领域材料条件如何使问题可研究。选择具有公开配套材料的 CS 论文，可以观察论文描述与实现、数据和评测之间的联系，检验跨材料知识的构建和使用；代码库、数据集、benchmark 因而是理解研究的证据来源，具体需要哪些材料取决于研究动作。

这比先规定系统必须包含几类资源、再以“CS 有这些资源”为理由更完整。可追踪的联系和部分机器可读材料提供实证条件，同时仍有关系隐含、信息分散及实验条件难以对应的缺口。不能将材料公开直接等同于 agent-ready，也不必预先声称整个 CS 领域都符合这些条件。

“发表快”等领域特征只有在与具体问题建立联系时才有解释力，例如持续新增材料带来的维护需求。当前若主要研究静态产物构建，材料可获取、关系可追踪、使用过程可核查是更直接的选择理由。

### 评价应验证产物与下游使用

分别评价产物的语义正确性、关系和证据支持，以及固定消费 Agent 在独立研究任务中的表现；检查条件改变后是否错误外推，并报告构建与重复使用的累计成本。

比较应给强模型直接阅读、在线 Agent、朴素结构化抽取及 KATS 风格用途记录等基线等价的材料访问条件和声明预算，区分材料增加、模型选择、知识表示与核验机制的作用。仅有最终 QA 或检索命中改善，不足以证明库中知识可靠。具体任务与质量标准仍需先讨论确定。
