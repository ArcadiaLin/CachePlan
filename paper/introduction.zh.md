# Introduction（中文讨论初稿）

> 2026-09-11 修订。按“渐进案例 → 需求特征与缺口 → 挑战 → 系统回应 → 评测”组织叙事。案例保留占位，待从样例论文集中选出并核查；系统机制和实验结果仍待补实。本文是中文草稿，英文稿尚未同步。

研究 Agent 从一个研究想法出发，需要发现值得阅读的工作、比较方法与实验条件，并选择能够支持后续验证的数据、benchmark 和实现。这些选择所需的信息分散在论文、代码库、数据说明、评测工具和引文上下文中：论文阐述研究问题与方法，数据和评测实现提供任务与指标的具体定义，资源使用记录和引文则连接起不同研究工作。如何将这些分散信息加工为有依据、可访问、可复用的研究知识，构成了面向研究 Agent 的数据管理问题。

**案例：`<某 query>`。** 考虑一位研究者希望围绕这个需求调研相关工作，并为验证自己的想法准备材料。随着候选和证据的积累，需求逐步展开为以下问题：

- **Q1：发现。** 哪些论文与我的研究需求相关，哪些值得优先阅读？
- **Q2：判断。** 看起来相关的候选是否满足我的条件？它们的问题定义、方法和实验设置有什么区别？
- **Q3：选择。** 哪些 benchmark 和数据适合检验我的想法，已有研究如何使用它们？
- **Q4：准备使用。** 有哪些实现与评测工具可以采用，需要确认哪些版本、配置和使用条件？

这个案例将围绕一次有证据支持的选择转折展开。设想初始检索返回了 `<表面相关的论文 A>`；检查 `<代码、数据、benchmark 或引文中的关键线索>` 后，Agent 发现它不满足 `<需求条件>`，并沿相关资源或引用关系找到 `<符合需求的论文 B>`。同一条线索也可能只是修正候选的排序或适用范围。具体转折将由真实材料确定，最终需要说明线索出现前后的选择及其依据。

在这一过程中，研究行动会相互影响。用于回答 Q3 的任务样例或评分代码，也可能改变 Q2 的相关性判断；资源与论文的关联可能重新打开 Q1 的发现过程；Q4 中发现的版本差异又可能促使研究者调整资源选择。因此，关联资源既可以服务于后续实验准备，也可以成为发现和理解论文的入口。

这一场景提出了三项相互联系的需求。首先，**相关性依赖具体研究意图。** 相似术语提供初始候选，判断还需落实到研究对象、任务条件和方法用途。其次，**发现与判断依赖跨材料关系。** 一份数据集如何构造、一个 benchmark 实际测量什么、某项工作如何使用已有实现，都可能影响哪些论文值得阅读。最后，**部分理解具有跨任务复用的价值。** 资源身份、任务定义、使用记录和实验条件可以供多个问题使用，而针对新需求的适用性判断仍需结合这些事实重新作出。

原始材料的可访问性为上述行动提供了基础，但从材料到选择仍需要语义加工。即使 Agent 能够搜索和阅读全文、访问代码与数据，它仍需确认资源身份，解释材料中的具体设置，并把这些信息关联回论文及当前需求。当这些加工结果只保留在一次查询的上下文中，后续任务就需要重新定位和组织相同依据。由此，我们关注的核心问题是：**如何构建一个持久的文献资源库，使从论文及关联材料中获得的知识能够支持不断具体化的研究需求，并保留重新判断和核查所需的上下文？**

这一问题包含三项挑战。第一，**从材料中构建足以支撑选择的知识。** 对案例中的 Q2 和 Q3，仅识别资源名称与链接还不够：系统需要解释资源承担的角色、任务设置和已有用法，并判断这些描述是否得到材料支持。作者提出资源时的原始用途、后续论文实际采用的用法，以及当前 query 下的适用性，需要分别表达。这要求抽取过程理解跨段落、跨材料的证据，并保留尚不能确认的内容。

第二，**组织能够支持不同发现路径的论文与资源关系。** 对 Q1，Agent 既可能从研究问题寻找论文，也可能从已有数据、benchmark 或实现寻找相关工作；对 Q2 和 Q3，它还需要比较不同候选的用途与条件。系统需要将分散材料中的同一实体和使用关系连接起来，同时保留名称相同、版本不同或用途不同的区别，使一次资源检查得到的线索能够用于后续检索和比较。

第三，**让已有知识能够被有条件地复用和核查。** 在 Q2–Q4 中，一条结论是否适用取决于其来源、版本和检查范围。论文声称发布代码、观察到仓库内容、成功执行程序与复现实验是不同的发现。系统需要保留这些区别，使 Agent 能够判断何时可以复用已有记录、何时需要返回原材料继续检查，并避免将某个任务下的结论当作普遍事实传播。

为此，我们研究 Papers for Agents（P4A）：一个面向研究 Agent 的文献资源库构建与访问系统。P4A 以已发表论文及公开关联材料为输入，通过推理式抽取构建资源身份、用途、实验条件和使用关系等记录，将其与来源证据一起持久保存。研究 Agent 从当前需求出发访问这些记录，发现候选、比较条件、选择资源，并在证据不足时继续查阅原始材料。其设计围绕知识构建、跨材料组织与可核查复用展开，使案例中的研究行动共享已有的材料理解。

围绕上述挑战，本文拟从三个方面开展工作：

- **有证据支持的资源知识构建。** 研究如何从论文与关联材料中提取和核查资源角色、任务条件与使用方式，为相关性和适用性判断提供依据。
- **面向研究需求的组织与访问。** 研究如何关联论文、资源及其使用记录，支持从需求到论文、从资源到论文的发现路径，并保留候选之间的重要差异。
- **可核查的知识复用与系统评价。** 研究来源、版本和检查状态的保留方式，分别评价资源库质量与 Agent 使用效果，再通过整组研究问题检验二者如何影响最终选择及成本。

为使案例与系统评价建立在同一材料基础上，我们计划从 P4A v1 已处理的论文出发构造样例论文集，首版以至少 200 篇为目标。我们将核查满足具体需求的种子论文，加入同 venue、表面相关但不满足条件的候选，再沿引文、共享代码和数据关系向 venue 外扩展，并保留扩展带入的干扰项。资源事实与相对于 query 的判断分别依据原始材料核查，已有抽取结果作为标注线索。贯穿案例将取自这个集合中的代表性 query，其作用是展示选择转折；总体结论由一组独立准备的 QA 支撑。

评价将分别考察知识构建的语义正确性、关系与证据支持，以及下游回答中的论文发现、条件判断、资源选择和使用准备。我们计划与 Agent 直接检索和外部 DeepResearch 比较：在相同原始材料访问条件下分析资源库的作用，在开放检索条件下比较实际任务效果，并记录各自的信息范围与预算。构建投入和查询成本将分别报告，以检验知识复用能否在改善研究选择的同时减少重复阅读与解释。具体机制、比较协议和实证结果将在后续补齐。
