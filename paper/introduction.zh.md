研究意图
    先明确 P4A 希望解决的问题，暂不围绕“如何区别于 AgenticScholar”倒推研究范围。“介于 AgenticScholar 与 ARA 之间”可以作为内部理解，正式叙事直接落在：面向通用研究 Agent 的论文知识产物表示与管理，即 artifact schema + resource interoperability。
    希望探索一种通用的论文知识表示 schema，并通过资源库实现产物的积累、关联、查询与使用。论文中的研究内容是表示对象，阅读、抽取和整理是形成产物的途径；产物既可以在预处理时构建，也可以在后续研究中逐步补充。
    通用 Agent 通过 tools 管理和使用这些产物，便于接入研究者已有的工作方式。Skill、MCP 等可作为接入形式的参考，暂不预设需要自建专用 Agent 规划与执行框架，也不将接入方式本身视为创新。

问题背景：
1. 大背景：Agent 辅助研究者开展科研正变得越来越普遍，参与文献调研、研究方案比较、代码编写和实验开展。在这些活动中，Agent 不断阅读和使用已有论文，提炼方法、实验条件、结论及其依据.
2. 论文与学术基础设施的组织方式：**然而**，论文主要面向人类交流与论证组织，却日益由 AI Agent 阅读和使用（Scientific papers are optimized for human communication, but increasingly consumed by AI agents）。
3. 跨会话的持久记忆问题：研究工作通常跨越多次会话，但一次会话中形成的论文理解，未必能在后续会话中被找到并接续使用。会话记录即使已经保存，其中的知识也未必按论文和研究对象得到组织，相关结论、依据和后续修订可能散落在不同位置。新会话因而仍需恢复此前的阅读上下文，甚至重复阅读和提取，已有理解难以持续积累为可查询、可补充的研究知识。
4. 跨 Agent 应用的成果复用问题：研究者还可能在不同 Agent 应用之间切换，分别开展调研、写作或实验。一套应用生成的阅读成果，即使已经持久保存，也未必能被另一套应用直接发现、理解和继续使用。不同的产物组织方式、上下文约定和访问接口，会使后续 Agent 需要重新解释已有记录、匹配研究对象，并恢复与原始证据的联系。因此，跨会话保存知识之外，还存在跨 Agent 应用交接和复用知识成果的问题。
5. 面向 Agent 用户的数据管理缺口：上述需求指向一个能够独立于研究会话和 Agent 应用持续存在的论文数据库。其使用关系类似应用使用 SQLite：通用 Agent 负责研究决策，通过具有明确语义的工具操作论文知识，如同应用通过 SQL 使用数据库；论文库负责知识的表示、持久保存、关联、查询与更新。当研究者开始新会话或更换 Agent 应用时，已经积累的知识仍能被访问、理解和继续补充。这里需要解决的 gap 是如何让论文知识成为外部 Agent 可共同操作的持久数据资源，使研究流程可以变化、Agent 可以替换，而知识积累能够延续。SQLite 和 SQL 用于说明这一职责边界，具体存储实现与操作接口仍待研究。
要解决的核心问题：
  如何将论文中的研究内容构建为具有共同表示和访问约定的知识产物，并使通用 Agent 能够跨任务发现、引用、补充和复用这些产物？
现有系统为什么没有做到：
1. 以文档和书目记录为中心的学术基础设施便于保存、检索和引用论文，但保存论文并不自动保留 Agent 阅读时提炼出的研究知识。当这些成果只以会话回答或独立笔记的形式留下时，方法、条件、证据及其关联仍需由后续使用者重新整理。由此，论文的可获取性与阅读所得知识的可积累、可复用性之间暴露出管理上的缺口。
2. 已有 agentic 学术系统的设计边界：[AgenticScholar](../references/papers/2026-AgenticScholar-reread/paper.txt)（Fig. 2、§3–5）等工作已经将论文知识组织、研究查询规划和算子执行整合为自包含系统，支持知识持久存储和多类学术分析。这种模式将 Agent 对研究需求的分解与执行逻辑纳入系统内部，用户把需求交给系统，由系统组织研究查询的处理流程。然而，当研究者希望继续使用自己的通用 Agent，自主决定研究步骤，并将论文库作为可查询、可写入和可维护的数据资源时，所需的是另一种职责划分：Agent 作为数据库用户，数据库提供可组合的数据操作。AgenticScholar 展示的设计与评价，尚未将独立 Agent 应用对研究产物的共同读写与持续维护作为核心问题；将分析系统封装成一个外部工具，也不会自动建立这些数据访问与管理约定。

贡献
面向研究 Agent 的论文知识数据模型。 研究可独立访问和组合使用的知识单元，明确其条件、证据与关联，并定义供外部 Agent 使用的查询和管理操作语义。区别于数据库 + api
论文知识产物的构建与关联管理方法。 从论文中识别和组织上述知识对象，处理不同位置与阅读过程中的描述对应，使知识能够在保留来源和条件的基础上逐步积累。
系统实现与跨领域评价。 实现支持通用 Agent 访问的论文数据库，在计算机科学和经济学中评价产物质量、研究任务效果，以及跨会话、跨 Agent 的复用价值与总成本。

评测
检验外部 Agent 使用 P4A 后，能否更准确地检索研究、撰写有依据的综述，并在新会话或其他 Agent 应用中继续使用和补充已有知识，减少重复阅读与处理。检索和综述是应用任务；跨会话、跨 Agent 和持续补充是这些任务的使用条件。

领域语料和任务来源：
计算机科学与经济学，每个领域选择多个研究主题，覆盖不同的研究需求与论文内容

Agent 在辅助研究者发现相关工作、比较研究方案和开展实验时，需要综合利用论文及其关联材料中的研究知识。一项研究的问题、方法、实验设置与结果分布在正文、图表和附录中，实现与评测细节还可能由配套材料补充；不同研究又通过引文、共享资源和方法沿用建立联系。Agent 要据此作出有依据的判断，需要理解各部分内容的含义，以及它们在具体研究中的对应关系。

这些材料主要围绕研究的论证与报告组织，研究主张、支撑证据和适用条件之间的联系并不总以可独立访问的知识记录显式表达。例如，判断某种方法能否用于当前问题，可能需要将正文中的方法描述、表格中的实验结果、附录中的设置和配套材料中的实现相互对照。即使已经找到相关内容，Agent 仍需确认它们是否对应同一实验、结论依赖哪些条件，以及这些依据是否足以支持当前选择。这种跨内容、跨材料的理解与核查，构成了从已有研究到后续研究行动之间需要完成的知识整理工作。

我们由此关注：**如何将论文及其关联材料转化为 Agent 可按需访问、核查和复用的知识产物？** 这种产物需要将问题定义、方法、实验条件、研究结论及关联资源组织为具有明确语义的记录，并保留它们之间的关系、来源证据与适用边界。Agent 可以据此发现与甄别候选、追踪和引用研究依据，并为复现和使用已有方法或资源获取所需知识；在依据不足时，也能够返回原始来源继续检查。我们将这种面向 Agent 使用的研究产物称为 **agent-ready artifacts**。

计算机科学为研究这一转化过程提供了合适的实证场景。预印本与公开发表渠道便于获取新近研究，明确的任务定义、方法描述和实验设置为内容解析提供线索，公开配套材料则为检查实现与评测过程提供了进一步依据。在具有这些条件的研究中，代码库、数据集和 benchmark 提供了实现细节、数据构造与评测协议等可核查信息，可以与论文中的论述相互参照。因此，我们选择计算机科学中具有公开配套材料的论文作为初始实证范围，利用其材料可访问、研究对象及其关系可追踪的条件，考察如何构建和核查面向 Agent 的研究知识。即使这些材料已经公开，它们是否对应同一项实验、某项结论依赖什么条件，以及已有用法能否支持新需求，仍需跨材料理解与判断。

**案例：`<某 query>`。** 考虑 Agent 接到研究者提出的这一需求，需要调研相关工作，并利用已有研究验证想法。我们将其使用论文及关联材料的行为概括为以下四类活动，以 A1–A4 标记，其中 A 表示 Activity：

- **A1：发现。** 根据研究者的需求检索论文，形成相关工作的候选集合。
- **A2：甄别。** 结合问题定义、方法和实验条件精炼候选，判断是否纳入考虑及其优先级。
- **A3：扩展与引证。** 沿引文、方法沿用和资源关联追踪相关工作与材料，补充研究上下文，并引用相关研究与证据支撑当前判断或研究方案。
- **A4：复现与使用。** 采用已有方法或资源开展实验，包括运行实现、复现结果或将其用于新的研究任务，并核对所需的版本、配置和评测条件。

如案例所示，Agent 可以围绕 `<某 query>`，辅助研究者开展 A1–A4 中的一类或多类活动。这些活动可交织开展、相互影响：A3 中追踪到的任务样例或评分代码可能改变 A2 的甄别结果，A4 中观察到的版本差异或实验结果可能促使重新检查已有判断，沿引文与资源关系发现的新工作又可能触发新的检索（A1）。因此，Agent 需要将论文内容与材料证据联系起来，根据当前需求理解它们对后续研究活动的影响。

当其他研究需求涉及同一篇论文或同一资源时，其中的问题定义、使用记录和实验条件具有复用价值；新需求下的适用性则需要结合这些事实重新判断。逐次从原始材料中获取这些知识，会产生重复检索、阅读和推理的成本。这进一步提出了知识组织的需求：将已有的理解与核查结果保存为可访问的记录，保留其证据和成立条件，使后续研究行动能够复用已有知识，并在需要时继续检查。

构建这样的研究产物面临三项挑战。第一，**形成有证据支持的语义关系。** 论文中的方法、实验条件和结论可能分散在不同位置，相关实现与评测材料又提供了不同层次的细节。为支持 A2 的甄别和 A3 的引证，系统需要确认研究主张由哪些实验与结果支持，相关资源在其中承担什么角色、采用了什么设置，防止将分别正确的信息拼接为不成立的关系。作者的概括性描述、特定实验中的实际用法，以及当前需求下的适用性，需要分别表达，并保留无法确认的内容。

第二，**组织能够服务不同研究行动的知识单元及其联系。** A1–A4 需要的信息粒度不同：发现可能从问题或方法出发，甄别需要条件与证据，扩展与引证需要研究关系及其支撑依据，复现与使用则需要更具体的版本、配置和评测协议。面向 Agent 的组织形式需要明确哪些内容可以独立访问、哪些关系必须一起保留，以及如何从一条记录追溯到论文和关联材料。跨论文整合还需要区分同名资源的不同版本与用法，使已有知识能够支持后续检索和比较。

第三，**保留可核查复用所需的边界。** 一条记录是否足以支持当前行动，取决于其来源、版本、检查范围和研究需求。论文声称发布代码、观察到仓库内容、成功执行程序与复现实验是不同的发现。组织形式需要表达这些证据状态，使 Agent 能够判断何时可以采用已有记录、何时需要补充检查，并避免将特定条件下的结论当作普遍事实复用。

为此，我们研究 **Papers for Agents（P4A）**，探索面向研究 Agent 的研究产物组织形式及其构建方法。P4A 通过内容解析、语义理解与材料核查等预处理流程，将论文及其公开关联材料中的研究内容整合为有依据、可访问、可复用的知识记录，并以持久化文献资源库承载这些产物。我们关注如何通过推理式抽取建立论文内部及关联材料之间的语义关系，将事实、来源证据、检查状态与适用条件共同组织起来，使 Agent 能够按需获取已有知识，并继续追踪尚未解决的问题。具体记录粒度、组织结构与访问方式仍需围绕明确的任务和证据环境确定。

围绕上述问题，本文拟从三个方面开展工作：

- **面向 Agent 的研究产物组织。** 研究如何表达论文中的研究内容、关联材料及其关系，保留来源、条件和检查状态，为上述四类研究活动提供支持。
- **基于推理与核查的产物构建。** 研究如何从论文及关联材料中抽取、对齐和核查语义关系，处理证据不足或不一致的情况，形成能够支持后续研究行动的记录。
- **产物质量与使用价值的评价。** 独立评价产物的语义正确性、关系正确性与证据支持，再考察 Agent 使用这些产物后能否作出更有依据的研究选择，以及知识复用是否减少重复阅读与解释。

我们计划在具有独立核查依据的 CS 论文及关联材料集合上，选择明确的研究任务开展评价。贯穿案例用于展示知识产物如何影响一次具体判断，整组任务用于考察其效果是否能够推广到其他需求。方法比较需要在相同原始材料访问条件和声明的预算下进行，设置直接阅读检索、常规结构化抽取等对照，以区分组织形式、推理与核查带来的作用；开放检索下与外部 DeepResearch 的比较可作为补充，并记录各自的信息范围。构建投入与使用成本将分别报告，通过涉及共享论文和资源的多个需求检验复用价值。具体任务范围、比较协议和质量标准仍待确定。

这项研究旨在探索一种使已发表研究更便于 Agent 发现、理解和利用的组织形式。通过将分散在论文及关联材料中的内容转化为可访问、可追溯、带有适用边界的研究知识，我们希望为 Agent 辅助研究者开展后续工作提供可复用的基础；其有效性需要由产物质量和实际研究行动共同检验。
