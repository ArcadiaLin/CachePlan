# Introduction（中文讨论初稿，研究行动版）

> 2026-09-10 修订。与 `main.tex` 的英文叙事对应。案例为说明性场景，尚待真实资源核查。方法与实验未确定，末段列出研究工作方向，不作为已完成贡献。Community 留在系统设计讨论中。

研究 Agent 需要将研究问题转化为具体选择：哪些工作值得阅读，哪些资源可以采用，以及如何使用它们。这些选择涉及论文、数据集、benchmark 和代码库；每类材料提供推进研究想法所需的部分信息。为了支持这一过程，我们研究如何将已发表论文及关联材料中的信息组织为可复用的研究知识，方便 Agent 发现和使用研究成果。

考虑一位研究者正在开发提升长上下文指令遵循能力的方法，请 Agent 调研相关工作并准备实验。这一需求逐步展开为以下问题：

- **Q1：发现。** 哪些工作与这个想法相关，哪些值得优先阅读？
- **Q2：判断。** 这些工作的研究问题和实验条件，与我的设想有什么区别？
- **Q3：选择。** 哪些 benchmark 和数据适合检验我的方法，已有研究如何使用它们？
- **Q4：准备使用。** 有哪些实现与评测工具可以采用，使用前需要检查什么？

期望结果是有依据的论文与资源选择，以及继续开展工作所需的信息。这些行动也可以反复发生：实验条件不匹配可能改变检索方向，检查实现后也可能需要重新选择 benchmark。

这个案例体现了三项需求。首先，相关性取决于研究者的使用意图。术语相似的工作只是待检查的候选，选择还需要理解问题、假设与实验背景。其次，决策依据跨越不同材料。回答 Q3 和 Q4 可能需要同时参考论文对 benchmark 的描述、数据说明和仓库文档。最后，一部分理解可以服务于后续问题和任务。资源用途、已有用法与实验设置的价值可以超出最初阅读它们的那次交互。

这些需求揭示了原始材料访问与研究决策所需知识之间的 gap。Agent 可以搜索和阅读原始材料，但仍需定位细节、解释其作用并组织选择依据。如果这些理解只留在单次交互中，后续任务可能重复其中的工作。持久资源库提供了保存和复用这些理解的机会。核心问题是：如何构建和组织这样的知识，使其支持不断具体化的研究需求，同时保留判断适用性所需的证据与条件？

这一问题包含三项挑战。第一，**构建的信息需要支持研究选择。** 找到 benchmark 或仓库只是获得入口；回答 Q3 还需要理解它评测什么以及已有研究如何使用它。资源原始用途与后续研究记录的用法需要区分，而是否适合新的想法，应由 Agent 根据这些依据进一步判断。

第二，**组织与访问需要服务不同研究需求。** 同一资源可能因评测设计而适用于一个任务，也可能因实现方式而适用于另一个任务。系统需要呈现跨材料背景，并保留决定具体论文、数据或工具是否适用的差异。领域层面的整理也需要支持进一步定位和检查单个资源。

第三，**复用需要保留进一步检查的依据。** 压缩后的描述可能遗漏限制，外部材料也可能发生变化。资源库需要保留来源、适用条件和检查范围。论文声称发布代码、观察到仓库和成功执行是不同证据；准备使用资源的 Agent 需要知道已经获得什么依据，以及哪些问题尚未解决。

为此，我们提出 Papers for Agents（P4A）的系统设计，研究从已发表论文及其关联资源中构建和访问可复用的研究知识。系统旨在支持 Agent 发现相关工作、判断适用性、选择配套资源并准备使用。P4A 围绕持久资源库组织资源描述、研究背景、已有用法与来源依据，由 Agent 理解材料并构建知识，下游研究 Agent 访问这些知识，并在需要时返回原始材料继续检查。系统处理已公开的信息，不以恢复未公开研究历史为目标。

我们拟从三个方面开展工作：其一，研究支持发现、判断与使用的资源知识表示，并保留证据基础；其二，构建使这些知识能够跨研究任务复用的加工与访问机制；其三，通过系统评测连接资源库质量与发现、选择及使用准备的效果。评测计划与能够访问相同原始材料和已有资源服务的 Agent 比较，衡量建库和下游成本，并分析关键设计的作用。最终要检验的是：预先加工研究知识能否改善研究选择，减少重复阅读和解释，以及这些收益是否足以支持构建投入。
