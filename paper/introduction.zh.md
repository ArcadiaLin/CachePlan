近年来，以 Claude Code、Codex 等为代表的通用 Agent 逐渐进入研究工作流。这类 Agent 并非针对单一任务设计，而是在研究者的本地工作环境中，通过调用工具、读写文件和执行程序，协助完成文献调研、研究方案比较、代码编写和实验执行等多种活动。由于这些任务通常依赖已有研究成果，Agent 需要持续阅读和使用论文中的信息，包括方法描述、实验条件、结论及其依据。

然而，论文主要面向人类读者组织信息与论证过程。关键内容往往分散于正文、图表和附录中，部分实验细节还需要结合代码仓库、模型和数据集等关联资源进行理解。因此，Agent 不仅需要检索论文，还需要将分散的描述、资源和证据联系起来，判断已有研究成果与当前任务之间的关联。

阅读所得知识会在后续调研、写作与实验中被反复需要，其使用也可能跨越多次会话和不同 Agent 应用。保存这些成果，并使后续 Agent 能够理解、补充和继续使用，是有效利用论文资源的重要环节。如果已有理解散落在会话记录与独立笔记中，后续 Agent 可能需要重新定位研究对象、恢复结论的成立条件，并再次核查原始材料，带来重复阅读和解释的成本。要使论文知识持续积累并服务后续研究，需要处理以下三项挑战。

**挑战一：可复用的论文知识表示。** 论文中的研究描述依赖其上下文：一项结果可能只对应特定方法版本、实验设置或研究样本，其支持证据又分布在文字、表格和图中。将这些描述转为可独立访问的记录，需要明确研究对象、适用条件及其语义关系，使记录在脱离原论文和阅读会话后仍能被正确理解、组合与核查。跨论文关联还需要保留研究条件的差异，区分作者报告的主张、材料中的观察与后续核查所得的发现，避免将分别正确的信息组合成不成立的结论。

**挑战二：知识的持续积累与维护。** 对同一论文的理解可能在多次阅读中逐步形成：初次阅读提取方法与结果，后续检查补充实验设置，新的证据又可能修正此前的判断。保存各次回答仍不足以明确这些成果之间的关系。系统需要识别不同描述是否对应同一研究对象，区分已有知识的补充、修订，以及不同版本或条件下应当并存的发现，并保留来源与修订依据。这样，后续会话才能接续已有知识，也能检查一条记录如何形成和变化。

**挑战三：知识在研究环境中的接续使用。** 后续 Agent 需要能够发现已有资源，取得与当前任务相关的知识，并将新增理解写回资源库。共同表示之外，还需要明确查询、引用与更新的操作语义，使不同应用能够一致地解释记录及其变化。同时，知识进入当前研究上下文时，需要控制内容规模，并保留判断所需的条件与证据入口。项目记忆中引用或概括的知识，也需要与资源库中的记录保持联系，使知识修订后，后续会话能够识别并处理过时内容。

这些挑战指向论文知识在持续研究过程中的管理问题。文档与书目管理为论文的保存、检索和引用提供了基础，持久笔记与 Agent 记忆则提供了保留阅读成果和项目上下文的途径。已有学术系统也已探索更丰富的知识组织：[AgenticScholar](../references/papers/2026-AgenticScholar-reread/paper.txt) 将知识表示、研究查询规划与算子执行整合在同一系统中，支持多类学术分析。本文关注通用 Agent 作为外部使用者的情形：研究者通过自己的 Agent 决定研究步骤，论文知识作为持续存在的数据资源，供不同会话和应用共同使用与维护。

在这一情形下，已有记录、项目上下文和后续写入之间需要建立可核查的联系。例如，若一次后续阅读修正了某项结果的适用条件，而另一应用仍依据此前的项目摘要开展比较，就可能继续使用过时的判断。解决这一问题，需要明确被修订的知识对象、依赖它的摘要，以及消费方获取修订的方式。本文据此关注从阅读成果到持久知识、再到项目记忆的衔接，研究其中的共同语义、证据保留与更新关系；现有方案对这些需求的覆盖范围，需要通过具体使用场景与对照评价加以核查。

我们的核心问题是：**如何将论文中的研究内容构建为具有共同表示和访问约定的知识产物，使通用 Agent 能够跨任务、跨会话、跨应用发现、引用、补充和复用？** 我们将这种面向 Agent 使用的论文知识产物称为 **agent-ready artifacts**。它们需要保留研究内容的来源、成立条件及相互关系，使后续 Agent 可以按需获取已有知识，并在证据不足时返回原始材料继续检查。

为此，我们研究 **Papers for Agents（P4A）**，探索面向通用研究 Agent 的论文知识数据库。P4A 关注知识产物的表示模式（artifact schema）及其在不同应用间的互操作（resource interoperability）：Agent 负责研究决策，通过可组合的工具操作访问和管理知识；论文库负责知识的表示、持久保存、关联、查询与更新。产物既可以在预处理时构建，也可以在后续阅读和研究任务中逐步补充，Skill、MCP 等可作为访问和使用产物的接入形式。

通用 Agent 通常通过文件读写工具保存阅读笔记，知识对象及其关系的组织与维护依赖每次任务中的具体处理。我们探索面向论文知识的语义操作，使 Agent 在记录研究发现时，显式关联研究对象、成立条件与支持证据，并明确本次写入与已有记录之间的关系。通过将知识表示与关联管理融入阅读成果的写入过程，P4A 支持知识在形成时进入可查询、可核查和可持续维护的资源库，供后续笔记组织、研究查询与项目记忆使用。

P4A 进一步探索将积累的论文知识用于 Agent 的项目记忆。具体而言，可以根据项目需求，从知识库中选择相关内容，形成带有关键条件、证据入口和记录引用的知识摘要，通过 [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) 等项目上下文入口接入具体应用。知识库保留详细记录，项目摘要帮助后续会话了解已有研究基础并继续按需访问。这里需要研究摘要的内容选择、压缩后的语义保留，以及源记录修订后的摘要更新，使项目记忆能够随研究进展得到维护。

围绕上述问题，本文拟从三个方面开展工作：

- **面向研究 Agent 的论文知识数据模型与操作语义。** 研究可独立访问、组合使用的知识单元，表达其条件、证据与关联，并定义供外部 Agent 查询、引用和更新的共同操作语义。
- **论文知识产物的构建与持续维护方法。** 从论文及必要的关联材料中识别和对齐研究对象，通过语义理解与证据核查组织知识；在保留来源和修订依据的基础上持续补充，并研究项目摘要与知识记录的对应及更新。
- **系统实现与跨领域评价。** 实现支持通用 Agent 访问和项目记忆接入的论文数据库，在计算机科学与经济学中评价产物质量、研究任务效果，以及跨会话、跨应用的复用价值与总成本。

评价拟围绕两类应用任务展开：检索与筛选，以及多论文比较与综述。前者考察能否找到符合研究需求的论文并给出有依据的筛选理由；后者考察能否正确比较研究内容，保留重要条件，并用适当证据支持综述中的主张。我们还将独立核查知识单元、关系及其证据支持，覆盖初始构建和后续写入。对于项目摘要，将进一步检查关键条件与依据是否保留，以及知识修订后是否仍沿用过时内容。

在这些任务中，我们计划分别考察首次使用、跨会话和跨 Agent 应用的使用条件。跨会话评价将在清除原会话上下文后，提出涉及部分相同论文的新需求；跨应用评价将由不同 Agent 应用交接已有资源，并检查后续写入能否被另一消费方正确使用。比较将在相同原始材料访问条件和声明预算下进行，拟选择直接阅读检索、持久笔记、通用 Agent 记忆及常规结构化抽取等对照，保留各方案允许使用的持久资源，并区分知识组织、维护机制和项目摘要带来的作用。结果将分别报告各领域、任务和消费 Agent 的质量，以及建库、维护、摘要生成与加载、各次任务使用的累计成本，检验知识积累能否在保持质量的同时减少重复阅读与处理。
