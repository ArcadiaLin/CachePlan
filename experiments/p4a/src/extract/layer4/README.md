# MinerU Layer 4 Scripts

This directory contains control scripts for PDF/MinerU Layer 4 extraction.

## Scripts

- `prepare_mineru_layer4.py`: build a per-paper input bundle, initial YAML templates, Kimi prompt, and run report.
- `apply_agent_judgment.py`: merge agent-written `agent_judgment.json` into controlled YAML outputs.
- `launch_kimi_layer4.py`: prepare prompts, launch multiple Kimi CLI processes, capture logs, merge JSON judgment, validate outputs, and write a batch report.
- `validate_layer4_outputs.py`: validate script-generated YAML plus JSON reports and write `quality_report.json`.
- `common.py`: shared helpers and enum definitions.

Run scripts with the project virtualenv so PyYAML is available:

```bash
cd /home/lzx/projs/p4a

.venv/bin/python src/extract/layer4/prepare_mineru_layer4.py \
  --paper-id 2025.acl-demo.16

python3 ~/.codex/skills/use-kimi-agent/scripts/run_kimi.py \
  --cwd /home/lzx/projs/p4a \
  --prompt-file data/processed/layer4/2025.acl-demo.16/agent_prompt.md

.venv/bin/python src/extract/layer4/apply_agent_judgment.py \
  --paper-id 2025.acl-demo.16

.venv/bin/python src/extract/layer4/validate_layer4_outputs.py \
  --paper-id 2025.acl-demo.16
```

The agent must manually construct `agent_judgment.json`; it must not manually
write or edit `paper_record.yml`, `resource_records.yml`, or any other YAML
file. YAML files are generated by `prepare_mineru_layer4.py` and
`apply_agent_judgment.py`.

Batch launcher:

```bash
.venv/bin/python src/extract/layer4/launch_kimi_layer4.py \
  --paper-id 2025.acl-demo.16 \
  --concurrency 1 \
  --timeout 3600 \
  --no-skip-existing
```

Each paper should produce:

```text
data/processed/layer4/<paper_id>/
  input_bundle.json
  agent_judgment.json
  paper_record.yml
  paper_record.base.yml
  resource_records.yml
  resource_records.base.yml
  agent_prompt.md
  agent_response.md
  resource_verification_report.json
  run_report.json
  quality_report.json
```

For a full ACL 2025 batch, use the launcher directly:

```bash
cd /home/lzx/projs/p4a
.venv/bin/python src/extract/layer4/launch_kimi_layer4.py \
  --concurrency 4 \
  --timeout 3600
```

By default, the launcher skips obvious proceedings/front-matter records such as
volume files without a numeric paper suffix and records whose warnings say they
are not research papers. Pass `--include-front-matter` only when you explicitly
want those files.

Useful dry run / preparation command:

```bash
.venv/bin/python src/extract/layer4/launch_kimi_layer4.py \
  --paper-id 2025.acl-demo.16 \
  --prepare-only \
  --no-skip-existing \
  --overwrite-prepare
```

The launcher passes only a short bootstrap prompt to Kimi and asks Kimi to read
`agent_prompt.md` from disk. This avoids command-line `Argument list too long`
failures when citation contexts or references are large.

If merge or validation fails, the launcher writes `agent_repair_prompt.md` with
the error details and asks Kimi to repair only `agent_judgment.json`. The default
`--max-retries 2` gives Kimi two repair attempts after the first extraction.
