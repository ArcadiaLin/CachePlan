# E07 — P4A 样例论文集构造

状态：2026-09-11 整合目标与方案。p0 已实现，已有 952 篇语料复制与校验报告；p1–p4 尚未开始。本次仅更新文档。

## 目标与文档入口

按照用户确定的五步路线，从 P4A v1 已处理论文出发，构造具有可核查 ground truth 的候选池，用于案例寻找和后续 QA 评测准备。第一版以至少约 200 篇论文及相关资源为规模目标，从池内选择一个有“选择转折”的代表性 query 展开叙事。

目标、ground truth 和交付要求统一见[候选池构造与案例筛选](../../docs/experiments/e07-p4a-case-pool/README.md)。已有案例按同一模板保留：

- [A/B：轨迹复用、长上下文指令遵循](../../docs/experiments/e07-p4a-case-pool/README.md#case-a)；
- [C–H：Claude 来源案例](../../docs/experiments/e07-p4a-case-pool/case-candidates-claude.md)；
- [I–M：Kimi 来源案例](../../docs/experiments/e07-p4a-case-pool/case-candidates-kimi.md)。

外部案例提供需求与资源线索，需与本地种子及真实扩展路径对接；暂未对接的继续保留为备选。A/B 是初始需求，其他案例可按材料情况进入，尚未确定唯一主案例。

## 五步筛选主线

先明确 query 及其满足条件，再进行以下步骤：

1. **种子集：** 从 P4A 已处理的论文中选真阳性。先用资源数量、记录类型、URL 等结构性信号定位材料充分的候选，再回到原始材料核查与需求的匹配。
2. **第一批噪声：** 同 venue、关键词或主题接近，实际不满足需求的困难候选；逐项说明不满足什么。
3. **向外扩展：** 沿引文、共享代码库、共享数据集等关系，从 ACL 扩展到 venue 外，寻找可能被初始检索遗漏的正向候选，保留路径与证据。
4. **第二批噪声：** 保留扩展过程中捎带的无关论文，记录被带入的原因和不满足需求的条件。
5. **代表性案例：** 从候选池中选择资源或引文确实改变论文发现、判断或选择的 query，关联回论文、资源与 ground truth。

候选的进入途径与相对于 query 的标签分别记录。噪声采样可能发现正例；共享资源不等于相关，证据不足也不等于负例。

## 数据基础与核查边界

源数据为 [data/raw/p4a-v1/](../../data/raw/p4a-v1/README.md)，含 3321 篇 ACL 2025/2026 论文的处理产物，各层覆盖见源目录说明。p0 从 `data/processed/e01/n0_fixed_time.jsonl` 的“961 观测集”提取 952 篇不同论文。

已有产物：

- `data/processed/e07/corpus/<paper_id>/{mineru,layer4,cite}/`：952 篇的全文 markdown、Layer4 记录和引用材料。该副本不意味着已缓存每篇关联的外部代码与数据。
- [p0_corpus_summary.json](../../data/processed/e07/p0_corpus_summary.json)：记录复制与校验结果；每层文件数和字节数一致，另有 20 篇的抽样哈希比对。已登记 `2026.acl-long.165` 缺少 `layer4/agent_judgment.json`。

当前 952 篇是初始筛选语料；其余 v1 论文及 venue 外论文可以通过步骤 3 扩展进入候选。最终池的范围不限于 p0 复制目录。

依据用户的 [v1 可信度声明](../../data/raw/p4a-v1/README.md)：

- **Layer4 为当前基础。** layer4_v2 已从本地副本移除，原始归档未动。
- **抽取记录是线索。** description、relation_type、evidence、availability_check 等不能直接用作已核查事实。资源数量、类型与 URL 可用于初筛，但本身也不保证内容和关系正确。
- **Ground truth 分两层。** 资源身份、版本与关系事实，以及相对于具体 query 的满足条件，分别依据原始材料核查。种子“真阳性”在复核后确认。
- **扩展材料按需补齐。** 语料外论文先登记为线索；纳入正式标签或案例前补齐必要证据。只核查最终主案例不足以形成整组 QA 的 ground truth；其余未核查部分保留状态。
- **取证状态明确。** 区分论文声称、材料观察、执行成功与实验复现；“关键词检索难命中”与“资源改变选择”需实际记录支持。

## 阶段计划

| 阶段 | 工作与五步路线的对应 | 状态 |
| --- | --- | --- |
| p0 | 筛出并复制 952 篇初始语料，校验来源与副本 | 已实现，已有产物 |
| p1 | 从 resource_records 建立可追溯的 paper–resource 边，整理引用入口，语义待核查 | 未开始 |
| p2 | 步骤 1–2：固定当前需求条件，核查种子正例与同 venue 困难候选 | 未开始 |
| p3 | 步骤 3–4：沿共享资源和引用向外扩展，保留自然干扰项并核查标签 | 未开始 |
| p4 | 步骤 5：汇总池与 QA、比较案例，输出证据表和代表性叙述 | 未开始 |

p1 提供关系线索，不自动完成资源同一性或关系语义核查。p2–p4 的种子阈值、噪声比例、扩展深度和边优先级在看清本地材料后确定；本计划不提前写死。

当前工程下一步仍是 p1 的资源与引用线索整理。未实现阶段的具体脚本与运行按仓库工作节奏另行推进，本次文档整合没有执行新阶段。

## 交付与后续评测

交付候选池清单、进入路径、资源事实与需求标签证据表、一组 QA 草案、候选比较和一页代表性案例；同时报告材料缺口、未核查项与未出现转折的结果。案例使用同一池中的论文和证据。

候选池首先服务案例核查，也为后续评测准备。正式比较 P4A、Agent 直接检索和外部 DeepResearch 前，需要另行确定 QA、证据范围、质量标准、预算与独立核查方式，区分同材料比较和开放检索比较，报告构建与查询成本。当前产物不构成方法优越性的证明。

## 现有运行入口

```bash
cd experiments/e07-p4a-case-pool
make setup    # 委派给仓库根
make p0       # 重建 952 篇复制子集，并执行校验
make verify   # 当前依赖 p0，会重新复制并校验
```

当前 p0 会先清空 `data/processed/e07/corpus/` 再复制；这是现有实现的运行行为。正式标注与后续扩展材料的位置需在对应阶段确定，避免与可重建的 p0 产物混放。

仓库根 uv workspace 成员，`dependencies = []`。不要在本目录直接运行 `uv sync`，使用 `make setup`。
